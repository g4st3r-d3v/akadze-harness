# Процесс разработки

How-to: как задача akadze проходит путь от пула до PyPI. Черновик, ждёт подтверждения владельца.

## Где что лежит

- **Зачем и что** — этот репозиторий: роадмап волны (порядок, причины) и пул задач (границы, имена, условия готовности). Номер задачи — `W<волна>-<n>`.
- **Код** — `akadze`, ветки от `origin/main`, PR в `main`. Заметки о дизайне в репо кода не копируются.
- **Трекер** — пул задач в харнессе. GitHub issues — только для багов от пользователей и для задач, которые владелец явно перенёс.

## Цикл задачи

1. **Бриф.** Читаем HUB → роадмап волны → пул → код. Пишем: как сейчас, что делаем, вопросы. Стоп до ответа владельца.
2. **Спека.** Если меняется поведение или имя — сначала правка пула (или новой заметки) PR-ом в харнесс. Расхождение кода со спекой правится в одну из сторон явно, а не молча.
3. **Код.** Отдельный worktree на задачу, ветка `feat|fix|chore|ci|docs/<slug>`. Conventional commits, ломающее — с `!`. Тесты на настоящем Postgres, AAA, один act.
4. **Gate.** Локально `ruff check akadze tests` и `mypy`; `pytest`, если есть Postgres. Иначе — CI на PR (`gh pr checks --watch`).
5. **PR.** Тело на английском: Summary, Tests. Ссылка на задачу — номером (`W5-1`). Без упоминаний внешних продуктов и приложений-потребителей.
6. **Саморевью.** До показа владельцу агент ревьюит свой PR отдельным проходом (в Claude Code — `/code-review high <PR>`: свежий контекст, не автор). Каждая находка: исправить коммитом в ту же ветку или отклонить с причиной. Итог — комментарием в PR: что исправлено, что отклонено и почему. CI снова зелёный.
7. **Merge.** Squash, только после «да» владельца.
8. **Синхронизация.** После merge — отметка в пуле (`[x]`, номер PR, фактическое имя, если отличается), строка в HUB при новом решении.

## Релиз

Только по явной просьбе владельца.

1. PR `chore: bump package version to X.Y.Z`: `pyproject.toml` и `akadze/__about__.py`.
2. После merge — только тег: `git tag vX.Y.Z origin/main && git push origin vX.Y.Z`. GitHub release руками не создаётся: его делает workflow `release`.
3. Проверка: run `release` зелёный, версия на PyPI, release с `dist/*` на GitHub.
4. Харнесс: строка версии в HUB, итог волны в роадмапе.

Номер версии до 1.0: минор — волна или ломающее изменение; патч — исправления и небольшие аддитивные изменения, нужные потребителю раньше волны. Окончательно — W5-2 в [[11 — Пул задач после 0.4.0]].

## Агенты

Код и PR ведут агенты (Cursor, Claude Code). Правила для них — `AGENTS.md` в обоих репозиториях. Агент не делает merge, тег и релиз без «да» владельца, не делает force-push `main`, не добавляет брокеры и не ломает публичный API без вопроса.
