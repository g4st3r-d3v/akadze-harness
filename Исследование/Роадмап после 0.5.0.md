# Роадмап akadze после 0.5.0

Состав и вопросы согласованы владельцем 2026-10-21.

Wave 5 дала продуктовые примитивы и быстрый claim по умолчанию (`0.5.0`). Перед Beta нужен ответ на п.3 критериев из [[12 — Публичная поверхность и критерии Beta]]: нет ли потери задач и двойного выполнения. [[13 — Аудит кода 0.5.0]] потери не нашёл, но нашёл нарушение лимитов при гонке, падение воркера на ошибке базы и повторные запуски. Поэтому Wave 6 — волна надёжности. Задачи и условия готовности — в [[14 — Пул задач после 0.5.0]].

## Задачи волны

| Задача | Зачем сейчас | Выпуск |
|---|---|---|
| W6-1 Лимиты при гонке claim | `max_running` — обещание, ради которого лимиты заводят; сейчас оно держится только без конкуренции | `0.5.1` |
| W6-2 Воркер переживает ошибку базы | Failover Postgres сейчас роняет все воркеры кластера | `0.5.1` |
| W6-3 Типы аргументов | Сигнатура задачи обещает модель, приходит `dict` | `0.5.1` |
| W6-4 Сбой записи исхода | Живой воркер повторяет выполненную задачу | `0.5.1` (вместе с W6-2) |
| W6-5 Неизвестные задачи | Rolling deploy не должен сжигать попытки | `0.6.0` |
| W6-6 Синхронная задача и `timeout` | Параллельный запуск самой себя должен быть хотя бы описан | `0.6.0` |
| W6-7 Мелкие исправления | Хвост аудита: CLI, `drain`, миграции | `0.6.0` |
| W6-8 `fair` без полного скана | П.5 критериев Beta для `fair` | `0.6.0` |
| W6-9 Claim за заблокированной головой | Насыщенный ключ в голове не должен переводить claim в полный скан | `0.6.0` |
| W6-10 Отмена после выполнения | Строка не должна говорить «отменена», если тело отработало и побочные эффекты случились | `0.6.0` |

Порядок: W6-1 → W6-2 → W6-3, патч `0.5.1` (исправления текущего API, решение 12 в HUB). Затем W6-4…W6-7, W6-10 и перф W6-8, W6-9: обе меняют SQL claim, поэтому идут после W6-1 и с замером.

## Что волна не меняет

Python `>=3.13,<3.14`. At-least-once. Без другого брокера. Без HTTP в пакете. Без canvas. Схема меняется только если этого потребует W6-1 или W6-9. Список «не заводится» из [[10 — Пул задач после 0.2.0]] действует.

## Решения владельца (2026-10-21)

1. **W6-5.** Фильтр claim по зарегистрированным именам: задача ждёт воркера, который её знает.
2. **W6-6.** API не ломаем: документ и предупреждение, без запрета `timeout` для синхронных задач.
3. **A7, `overlap=False`.** Как сейчас: задача ставится, когда предыдущая закончилась, в пределах `grace`. Поведение описывается в документации (W6-7).
4. **A8, отмена running-задачи.** Если тело успело выполниться до конца — `succeeded` с результатом. Иначе — `cancelled`. То же для `expires_at`, истёкшего во время выполнения. Задача W6-10.
5. **Документ «Celery-replacement asks»** (PR #30, #31) — где он, неизвестно. Вопрос закрыт: действующие решения — те, что записаны в харнессе; ссылки в старых PR считаются историей.
