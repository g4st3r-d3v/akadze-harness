# Роадмап akadze после 0.2.0

**Итог волны (2026-10-20).** Все четыре задачи вышли в `0.3.0` (тег `v0.3.0`, 2026-10-11), PR #25–#27. Отличия от плана: снятие политики называется `clear_limit` и `akadze limits clear`; метрики — `akadze metrics render` (и просто `akadze metrics`). Очистку журнала стартов при снятии (`akadze.limit_starts`) код поначалу пропустил — доведено в 0.4.1 (#34). Tracing не начат. Следующая волна: [[Роадмап после 0.4.0]].

Пакет 0.2.0 закрыл Wave 3: ops (список / повтор / пауза), кластерный `limit_key`, частота стартов, текст метрик. Дальше смотрят на оператора без HTTP в пакете. Может ли он отменить задачу командой. Увидеть и снять лимит. Перечислить живых воркеров. Отдать строку метрик sidecar’у без своего скрипта. Состав задач и условия готовности — в [[10 — Пул задач после 0.2.0]]. История Wave 3 — в [[08 — Роадмап после 0.1.0]] и [[09 — Пул задач после 0.1.0]].

## Что уже не надо строить

`request_cancel` пишет `cancel_requested_at` для `queued` и `running`. Воркер применяет отмену. CLI для этого нет. `set_limit` умеет записать и заменить политику. Списка ключей нет. Снять строку нельзя. Таблица `akadze.workers` уже наполняется heartbeat’ом. Запроса и CLI нет. `render_metrics` уже возвращает текст Prometheus. Оператору всё ещё нужен свой вызов из Python.

Этого достаточно, чтобы очередь работала в кластере. Этого мало, чтобы жить с ней так же, как с платным экраном River/Oban или с тем, зачем годами открывают Flower — без второго сервиса и без порта в пакете.

## Почему снова не NOTIFY, не HTTP и не chord

Из «не заводится» в [[09 — Пул задач после 0.1.0]] **не** поднимаем `LISTEN/NOTIFY`, HTTP/web UI, протокол Celery, YAML-cron без деплоя, chord/group и блокирующее `.get()`. Доводы harness против них сильнее доводов конкурентов за. Новая волна только дожимает поверхность вокруг уже лежащих строк и функций.

Трейсинг (OTel / `meta.traceparent`) в обязательный скоуп не входит. В [[07 — Спрос на очереди задач 2026]] он ещё «не заводится». В пуле он помечен как опциональный и **не стартует**, пока владелец явно не поднимет флаг. Порта в пакете по-прежнему нет.

## Один релиз

Четыре обязательные задачи ниже можно делать в одном теге после `0.2.0`. Номер версии здесь не назначается. Внутри волны порядок удобный, не жёсткий по тегам: cancel и metrics опираются на уже существующий код; limits и workers добавляют запросы и одну команду снятия.

| Задача | Зачем сейчас |
|---|---|
| W4-1 CLI cancel | Паритет «отмена с экрана» командой; Python уже есть |
| W4-2 `list_limits` / unset + CLI `limits` | Видны ключи; можно снять политику; опечатка `limit_key` не остаётся вечным `queued` |
| W4-3 `workers list` | Ответ на топ Flower-issue про видимость воркеров — сначала CLI/SQL, не веб |
| W4-4 CLI для `render_metrics` | Sidecar получает строку без скрипта приложения |

### Cancel — только CLI и доки

Семантика `request_cancel` не меняется. Команда по-прежнему только просит остановку. Воркер применяет. CLI повторяет тот же вызов. В ops-доках пакета появляется тот же путь, что у `jobs requeue`.

### Limits — список, снятие, смена fail-closed

`list_limits` показывает строки `akadze.limits`. Опечатку в `limit_key` на задаче видно, сравнив с этим списком, а не ожидая вечный `queued`.

`unset_limit` удаляет строку политики и журнал стартов этого ключа. **Решение волны:** отсутствие строки в `akadze.limits` больше не блокирует claim. Пустой `limit_key` по-прежнему значит «лимита нет». Строка с политикой по-прежнему ограничивает. Так закрывается дыра «записал N, снять нельзя» без вечного капкана после удаления строки. Fail-closed из Wave 3 для «ключа без строки» этим решением снимается; видимость конфигурации даёт `list_limits`, не молчаливый отказ в claim.

CLI `limits` необязателен по форме, но входит в ту же задачу: `list` и `unset` / `clear` рядом с уже существующим `set_limit` в Python.

### Workers и metrics — чтение того, что уже есть

`list_workers` читает `akadze.workers`. Поля без секретов: идентификатор, хост, pid, очереди, время старта и heartbeat. CLI: `akadze workers list`.

CLI (или однострочный helper) для `render_metrics` печатает уже зафиксированный текст серий из W3-6. Пакет по-прежнему не открывает сокет.

## Что эта волна не меняет

Python `>=3.13,<3.14`. At-least-once. Без другого брокера. Без HTTP в пакете. Без canvas. Без YAML-расписаний в библиотеке. Без адаптера `django.tasks`. Трейсинг не начинается сам.
