# Роадмап akadze после 0.4.0

Черновик. Ждёт решения владельца по составу и номеру тега.

Wave 4 закрыла ops вокруг уже лежащих строк (`0.3.0`). `0.4.0` дала регистрацию под DI и расписания из конфига приложения. Пакет в формальной альфе, у него есть живой потребитель. Дальше вопрос не «чего не хватает оператору», а «что нужно, чтобы поверхность можно было заморозить». Состав задач и условия готовности — в [[11 — Пул задач после 0.4.0]]. История Wave 4 — в [[Роадмап после 0.2.0]] и [[10 — Пул задач после 0.2.0]].

## Что уже есть

`jobs.max_attempts` хранится на строке задачи. Его уже читают исход, rescuer и `requeue`. Задать его при постановке нельзя: берётся значение из определения задачи. README обещает «после Beta поверхность замораживается», но критериев Beta нигде нет. Раздел «Celery migration» в README — заготовка на пять строк.

## Задачи волны

| Задача | Зачем сейчас |
|---|---|
| W5-1 `max_attempts` в `using()` | Одно определение задачи обслуживает вызовы с разным бюджетом попыток. Потребитель упирается в общий потолок на `Retry` |
| W5-2 Критерии Beta и политика версий | Без списка публичной поверхности нечего замораживать. Без политики версий каждый тег решается заново |
| W5-3 How-to «Миграция с Celery» | Главный путь входа новых пользователей; сейчас это заготовка |

W5-1 аддитивна и не меняет схему. W5-2 и W5-3 — только документы и, возможно, тест на состав `__all__`.

## Что волна не меняет

Python `>=3.13,<3.14`. At-least-once. Без другого брокера. Без HTTP в пакете. Без canvas. Без YAML-расписаний в библиотеке. Без адаптера `django.tasks`. Трейсинг не начинается сам. Список «не заводится» из [[10 — Пул задач после 0.2.0]] действует.

## Открытые вопросы владельцу

1. Номер тега: W5-1 отдельным патчем раньше волны или всё одним минором.
2. Где живёт документ «Celery-replacement asks», на который ссылаются PR #30 и #31. Перенести его сюда, если решения из него действуют.
3. Нужен ли в волне ещё один функциональный пункт или волна — про заморозку.
