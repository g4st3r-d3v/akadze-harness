## Черновик: Show HN

> **Show HN: akadze – a Postgres task queue for Python with a Celery-like API**
>
> akadze is a background job library where PostgreSQL is the broker: jobs are rows, workers claim them with `FOR UPDATE SKIP LOCKED` and hold a heartbeat lease. If you already run Postgres, you get retries with backoff, cron/interval schedules inside the worker, per-key concurrency and rate limits, cancellation, and transactional enqueue (the job commits with your data or not at all) without Redis or RabbitMQ.
>
> The API is shaped like Celery (`@app.task`, `.using(...).enqueue()`), and there is a migration guide. It is async (SQLAlchemy + asyncpg), typed, MIT. Docs in English and Russian; benchmark against PgQueuer and Procrastinate in the docs, including where akadze is slower.
>
> It is alpha (0.x). Feedback on the API and on failure modes is what I am after.

## Черновик: r/Python (Showcase)

> **What my project does:** akadze runs background jobs from a PostgreSQL table: enqueue in your transaction, a worker claims with `SKIP LOCKED`, retries with backoff, cron schedules, per-key limits, cancellation, a CLI for ops and Prometheus text metrics.
>
> **Target audience:** Python services that already have Postgres and want Celery-style tasks without running a broker. Alpha, API may still change before 1.0.
>
> **Comparison:** vs Celery — no Redis/RabbitMQ, enqueue is transactional; vs PgQueuer — Celery-like task API, schedules, limits; currently slower on raw throughput (benchmark in docs); vs Procrastinate — SQLAlchemy engine sharing, faster in our benchmark.
